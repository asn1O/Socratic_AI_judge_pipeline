# Socratic AI Judge & Evaluation Pipeline: Architecture, Methodology & Technical Specification

---

## 1. Executive Summary & Purpose

The **Socratic AI Judge & Evaluation Pipeline** is an automated, multi-tiered evaluation, calibration, and benchmarking framework engineered to evaluate the pedagogical efficacy, factual correctness, and structural integrity of multi-turn Socratic tutoring conversations. While standard LLM benchmarks focus on single-turn reasoning or task completion, pedagogical evaluation requires assessing complex multi-turn dynamics: whether an AI tutor appropriately diagnoses student misunderstandings, provides minimal necessary scaffolding without giving away answers, adapts dynamically to student input, and preserves student agency.

To evaluate these attributes with scientific rigor, this pipeline implements an ensemble evaluation paradigm combining:
1. **A Tri-Judge LLM Ensemble:** Three distinct, automated LLM judges (`beam:cloud`, `gpt-oss:120b`, and `minimax-m3.1-flash`) operating on a standardized 10-dimensional rubric (3 Boolean safety dimensions and 7 discrete Likert scale dimensions $0 \in [0, 3]$) with mandatory turn-grounded evidence generation.
2. **Dual-Condition JEV SLM Verification:** Direct API integration with a specialized Small Language Model evaluator (**JEV**, `imajev-4b`), tested under two distinct observability conditions:
   - **JEV-1:** Evaluating raw conversation dialogue turns only (`jev_output/`).
   - **JEV-2:** Evaluating conversation dialogue turns enriched with internal pedagogical state classifications and tutor reasoning traces (`jev_output2/`).
3. **Multi-Stage Sanitization & Consensus Filtering:** Pre-evaluation structural verification, TF-IDF cosine deduplication, and a multi-judge consensus filter that excises dialogues flagged with factual inaccuracies, premature answers, or hallucinations across all parallel data trees.
4. **Targeted Human Annotation Benchmark Suite:** A curated corpus of **400 unique, disjoint conversations** sampled across three distinct methodologies (random unbiased baseline, metric-profile isolation, and severe judge disagreement) to calibrate automated evaluators against human ground truth.

Across **2,713 clean, validated conversations** generated by **16 distinct AI models**, the framework provides comprehensive statistical auditing, inter-judge agreement metrics (exact match rates, within-$\pm 1$ span reliability, Pearson correlation $r$), and automated publication-grade visualization suites.

## 3. Evaluation Rubric & Pedagogical Grounding

The evaluation framework formally defines **10 orthogonal evaluation dimensions** specified in `judge_prompt.md`. Evaluators evaluate the conversation holistically, assessing the interaction dynamics between tutor actions and student cognitive progression.

### 3.1 Boolean Safety & Pedagogical Invariant Dimensions

| Dimension | Type | Criterion (`True`) | Criterion (`False`) |
| :--- | :---: | :--- | :--- |
| **`correctness`** | `bool` | The tutor's explanations, mathematical operations, scientific mechanisms, and substantive guidance are factually and logically accurate. | The tutor introduces a substantive conceptual, logical, factual, or mathematical error. |
| **`premature_answer`** | `bool` | The tutor reveals the final solution, key formula, or complete derivation before the student has had an opportunity to work through the reasoning. | The tutor maintains appropriate withholding of final answers, prompting student reasoning. |
| **`hallucination`** | `bool` | The tutor introduces fabricated, non-existent, or spurious factual assertions not grounded in the domain problem. | No fabricated or counter-factual tutor content is present. |

### 3.2 Numerical Pedagogical Dimensions (Discrete Scale: 0–3)

Each numerical dimension is evaluated on a standardized 4-point discrete scale:
- **0:** Very Poor / Absent
- **1:** Weak / Severely Deficient
- **2:** Adequate / Competent
- **3:** Strong / Exemplary

| Dimension | Score 0 (Absent) | Score 1 (Weak) | Score 2 (Adequate) | Score 3 (Strong) |
| :--- | :--- | :--- | :--- | :--- |
| **socratic_guidance** | Guidance is pure exposition or answers; questions rhetorical | Statements/leading questions make up >=50% of turns | Genuine questions dominate, but tutor states 1+ steps | Every turn is a question eliciting student reasoning |
| **scaffolding** | Gives full solution or executes core step for student | Names key method/rule; student only carries it out | Useful partial nudge, but larger than necessary | Minimal nudge; escalates only if student stays stuck |
| **state_adaptation** | Rigid, script-following, unaffected by student inputs | Generic acknowledgement ("good"); generic next move | Addresses specific error, but misses 1+ critical signal | Fully tailored to student words, error root, and pace |
| **diagnosis** | No attempt to inspect student mental model | Superficial check ("do you understand?"); unverified assertions | Accurately spots error, but does not probe root cause | Probing questions uncover root cause before intervening |
| **student_agency** | Tutor does all heavy lifting; student only acknowledges | Tutor directs strategy; student turns are short or echoing | Student does most reasoning; tutor fills in 1 key step | Student generates all central reasoning, connections, checks |
| **progression** | No progress; student ends more confused than at start | Partial steps complete; major conceptual gap remains | Reaches answer with heavy support or no transfer evidence | Reaches solution via own reasoning with conceptual transfer |
| **coherence** | Contradictory, erratic, disjointed dialogue | Obvious contradiction, unaddressed student question, or repetition | Mostly coherent with 1–2 minor peripheral wording slips | Perfectly seamless dialogue; no ignored questions or drift |

### 3.3 Grounded Evidence Generation

For every evaluation, the judge must generate an `evidence` object containing exactly one concise justification sentence for each of the 10 dimensions, citing specific turn numbers:

```json
{
  "evidence": {
    "correctness": "Turns 4–10 maintain mathematically consistent calculations and correct physics laws.",
    "socratic_guidance": "Turns 4, 6, and 8 use questions to elicit student inferences rather than stating the next step.",
    "scaffolding": "Turn 4 provides a minimal nudge regarding the normal force while leaving arithmetic to the student.",
    "state_adaptation": "In Turn 6, the tutor immediately changes its prompt when the student confuses mass with weight.",
    "diagnosis": "Turn 2 directly asks the student to explain why they chose the sine function instead of cosine.",
    "student_agency": "The student formulates the free-body diagram equations independently across Turns 5 and 7.",
    "progression": "The conversation concludes with the student deriving the correct acceleration and stating the general principle.",
    "coherence": "All turns follow sequentially from the preceding student statements without contradictions.",
    "premature_answer": "The tutor never provides the numeric answer or formula prior to the student deriving it.",
    "hallucination": "All scientific assertions and problem constants match canonical Newtonian physics."
  }
}
```

Rather than relying on a single fallible judge model, the architecture implements a multi-evaluator consensus framework incorporating 5 distinct evaluation tracks:

```
                                +-------------------------------+
```

### 4.1 Ensemble Reliability Metrics

Evaluator reliability is quantified using three primary metrics across the 2,713 clean conversations:

1. **All 3 Exact Match % (`all_3_exact_pct`):**  
   The proportion of dialogues where Judge 1, Judge 2, and Judge 3 assign identical integer scores:
   $$\text{ExactMatch} = \frac{1}{N} \sum_{i=1}^N \mathbb{I}(J_{1,i} = J_{2,i} = J_{3,i})$$
   - Reaches **96.7%** on `coherence`, **94.3%** on `state_adaptation`, and **92.8%** on `progression`.

2. **All 3 Within $\pm 1$ Span (`all_3_within_1_pct`):**  
   The proportion of dialogues where the maximum inter-judge score divergence does not exceed 1 point on the 0–3 scale:
   $$\text{Within1Span} = \frac{1}{N} \sum_{i=1}^N \mathbb{I}\left(\max(J_{1,i}, J_{2,i}, J_{3,i}) - \min(J_{1,i}, J_{2,i}, J_{3,i}) \le 1\right)$$
   - Spans **91.0% to 100.0%** across all 7 numerical dimensions, demonstrating high multi-rater reliability.

3. **Pairwise Pearson Correlation Coefficient ($r$):**  
   Standardized covariance between evaluator pairs:
   $$r_{X,Y} = \frac{\sum_{i=1}^N (X_i - \bar{X})(Y_i - \bar{Y})}{\sqrt{\sum_{i=1}^N (X_i - \bar{X})^2} \sqrt{\sum_{i=1}^N (Y_i - \bar{Y})^2}}$$

### 4.3 Evaluator Generosity & Calibration Dynamics

- **Judge 2 (`gpt-oss:120b`)** is the most generous evaluator, assigning Score 3 in 68% of guidance, 87% of scaffolding, and 93% of agency cases.

- **JEV-2 (`imajev-4b` with State & Reasoning Context):** Providing tutor internal rationale clarifies pedagogical intent, increasing scaffolding Score 3 to 70% while maintaining disciplined standards on Socratic guidance (26% Score 3).

## 5. Detailed Component Breakdown & Implementation

### 5.1 Multi-Judge Evaluation Coordinator (`src/pipeline.py`)

The primary CLI evaluation script coordinates evaluation across LLM judge models:
- **Slot Architecture (`--judge-number {1, 2, 3}`):**  
  Each evaluation run targets a specific judge slot. This writes evaluations to specific fields (`judge_1`, `judge_2`, `judge_3`) within the output JSON records and tracks progress via slot-specific state files (`evaluation_state_judge_1.json`).
- **Resumable State Management:**  
  Persists completion state per source folder. If interrupted, subsequent runs inspect `evaluation_state.json` and resume immediately without re-evaluating completed dialogues.
- **Validation of Evaluation Payloads:**  
  Enforces `_validate_evaluation_payload()`, validating that all 10 required fields and the nested `evidence` object are present, correct in type, and strictly bounded to $\{0, 1, 2, 3\}$.

### 5.2 Universal Model Client Adapter (`src/model.py`)

Encapsulates network communication with OpenAI-compatible endpoints:
- Supports Google AI Studio, NVIDIA NIM, OpenRouter, and local inference engines.
- Tracks per-invocation and cumulative token usage (`avg_tokens_used`, `no_of_replies`).
- Implements exponential backoff and error classification (`RateLimitError`, `APIStatusError`, `APITimeoutError`).

### 5.3 Prompt Generation & Serialization (`src/prompt_generator.py`)

Hydrates `judge_prompt.md` with conversation payloads:
- Replaces `<<<CONVERSATION>>>` and `<<CONVERSATION>>` placeholders.
- Serializes input conversations with robust indentation and unicode preservation (`ensure_ascii=False`).

### 5.4 Specialized JEV Model Client (`src/jev_model.py`)

Provides direct integration with the JEV SLM system endpoint:
- **Default Endpoint:** `DEFAULT_JEV_URL = os.getenv("JEV_URL", "/v1/systemone")`.
- **Question Matrix (`FIXED_QUESTIONS`):** Configures standardized question prompts and explicit 4-level criteria for `socratic_guidance`, `scaffolding`, `state_adaptation`, and `diagnosis`.
- **Context Injection Formatting:** Formats conversation turns with configurable switches to include or omit tutor `state` and meta-cognitive `reasoning` traces (`format_conversation_state`).

### 5.5 JEV Batch Pipeline Engine (`src/jev_pipeline.py`)

Orchestrates batch evaluation runs through the JEV endpoint:
- Manages output partitioning between dialogue-only (`jev_output`) and state-enriched (`jev_output2`) directories.
- Maintains `evaluation_state.json` to support fault-tolerant resumed executions.

## 6. Dataset Sanitization, Deduplication & Quality Filtering

The repository provides a three-tiered pipeline to audit, clean, and deduplicate conversations prior to and during evaluation.

```
+-------------------------------------------------------------------------------------------------+
|                                1. Structural Validation                                         |
|                                (scripts/validate_conversations.py)                              |
|  - Turn numbering: 1..N monotonic increment                                                     |
|  - Alternating speakers: student -> tutor -> student ...                                        |
|  - Tutor state taxonomy: {Diagnosis, Support, Synthesis, Closing}                               |
|  - Ending invariants: Turn N-2 = Synthesis, Turn N = Closing                                    |
+------------------------------------------------+------------------------------------------------+
                                                 |
                                                 v
+-------------------------------------------------------------------------------------------------+
|                                2. TF-IDF & Cosine Deduplication                                 |
|                                (scripts/similarity_check.py)                                    |
|  - Concatenates full conversation utterances                                                    |
|  - Computes global TF-IDF vector representations across dataset                                 |
|  - Calculates pairwise cosine similarity matrix; flags pairs with cosine similarity >= 0.90     |
+------------------------------------------------+------------------------------------------------+
                                                 |
                                                 v
+-------------------------------------------------------------------------------------------------+
|                                3. Multi-Judge Consensus Pruning                                 |
|                                (scripts/remove_flagged_conversations.py)                        |
|  - Cross-examines Judge 1, Judge 2, and Judge 3 outputs                                         |
|  - Prunes conversation if ANY judge flags:                                                      |
|    * correctness == False                                                                       |
|    * premature_answer == True                                                                   |
|    * hallucination == True                                                                      |
|  - Synchronously updates data/, output/, and jev_output/ to maintain exact positional alignment |
|  - Logs removals to removed_conversations.log and removed_conversations.json                    |
+-------------------------------------------------------------------------------------------------+
```

## 9. Command-Line Usage & Pipeline Execution Commands

### 9.1 Data Validation & Deduplication
```bash
# 1. Inspect conversation structural validity (read-only check)
python3 scripts/validate_conversations.py

# 2. Automatically delete structurally invalid conversations from JSON files
python3 scripts/validate_conversations.py --delete-invalid

# 3. Detect duplicate conversations using TF-IDF cosine similarity (>= 90%)
python3 scripts/similarity_check.py
```

### 9.2 Running Multi-Judge Evaluation
```bash
# Evaluate conversations with Judge 1 (e.g. beam:cloud, slot 1)
python3 src/pipeline.py \
  --source-model-dir Google_gemini-3.1-flash-lite \
  --max-conversations 50 \
  --models-path models/model.json \
  --judge-index 0 \
  --judge-number 1

# Evaluate conversations with Judge 2 (e.g. gpt-oss:120b, slot 2)
python3 src/pipeline.py \
  --source-model-dir Google_gemini-3.1-flash-lite \
  --max-conversations 50 \
  --models-path models/model.json \
  --judge-index 1 \
  --judge-number 2

# Evaluate conversations with Judge 3 (e.g. minimax-m3.1-flash, slot 3)
python3 src/pipeline.py \
  --source-model-dir Google_gemini-3.1-flash-lite \
  --max-conversations 50 \
  --models-path models/model.json \
  --judge-index 2 \
  --judge-number 3
```

```bash
# Evaluate dialogues with JEV-1 (raw conversation turns only)
```

## 11. Conclusion & Pedagogical Impact

The **Socratic AI Judge & Evaluation Pipeline** provides an end-to-end, scientifically grounded methodology for evaluating AI-generated pedagogical interactions. By combining multi-judge LLM consensus, dual-observability SLM benchmarking (JEV-1 and JEV-2), strict multi-judge consensus flaw removal, and a calibrated 400-conversation human annotation pool, this pipeline establishes a reliable framework for benchmarking automated tutors and curating high-fidelity fine-tuning datasets for the next generation of Socratic AI systems.
